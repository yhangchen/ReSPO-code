# v0.8.0 Update Summary

Updated from verl v0.7.1 (base commit `bec9ef74 [misc] chore: bump version to 0.7.1 (#5602)`) to v0.8.0 (`upstream/release/v0.8.0`).

## Upstream Changes Incorporated

### `verl/` directory
- Replaced entirely with upstream v0.8.0 content (341 files changed, +21312/-30846 lines upstream).
- Major structural changes: `verl/workers/actor/dp_actor.py` and `verl/workers/megatron_workers.py` removed in v0.8.0.
- ZMQ socket path now uses `job_id`/`replica_rank`/`local_rank` scheme (replaces old device UUID approach).
- Megatron async checkpoint save now uses `AsyncCallsQueue` with `ImportError` fallback.
- IPC socket unlink before bind already included in v0.8.0.
- Python requirement bumped to `>=3.10`.

### Everything outside `verl/`
- 611 files changed upstream (+31422/-23131 lines).
- Updated: `.github/`, `docs/`, `examples/`, `tests/`, `pyproject.toml`, `Dockerfile`, CI workflows, etc.

## Custom Patches Re-applied on Top of v0.8.0

### 1. ROCR_VISIBLE_DEVICES fix (`verl/single_controller/base/worker.py`)
- Instead of raising `ValueError` when both `ROCR_VISIBLE_DEVICES` and `CUDA_VISIBLE_DEVICES` are set, silently drop `ROCR_VISIBLE_DEVICES` and trust `CUDA_VISIBLE_DEVICES`.
- Reason: GCP a3u nodes' Slurm gres plugin sets both env vars; ROCR is the AMD env var and is meaningless on NVIDIA.

### 2. Enable math_verify by default (`verl/utils/reward_score/__init__.py`)
- For `lighteval/MATH` and similar data sources, use `math_verify.compute_score` instead of `math_reward.compute_score`.
- Changed `data_source.startswith("aime")` to `"aime" in data_source or "amc" in data_source` for broader matching.
- Added `strict_box_verify=True` to `math_dapo.compute_score` calls.

### 3. math_dapo extracted_pred default (`verl/utils/reward_score/math_dapo.py`)
- Changed `extracted_pred` default from `None` to `""` when `boxed_pred is None`.
- Reason: Prevents `None == gt` comparison issues; empty string is a safer fallback.

### 4. Wandb resume support (`verl/utils/tracking.py`, `verl/trainer/ppo/ray_trainer.py`, `verl/trainer/config/ppo_trainer.yaml`)
- Added `resume_run_id` parameter to `Tracking.__init__()`.
- When `resume_run_id` is set, `wandb.init` uses `resume="must"` and the given run ID.
- Added `trainer.wandb_run_id` config option in `ppo_trainer.yaml`.
- Passed through in `ray_trainer.py` `fit()` method.

### 5. Training generations logger (`verl/utils/tracking.py`, `verl/trainer/ppo/ray_trainer.py`, `verl/trainer/config/ppo_trainer.yaml`)
- Added `TrainGenerationsLogger` class (mirrors `ValidationGenerationsLogger` but for training rollouts).
- Added `_maybe_log_train_generations()` method to `RayPPOTrainer`.
- Called after rollout data logging in the training loop.
- Added `trainer.log_train_generations` config option (default: 0, disabled).
- Logs deterministically sampled training samples as a wandb/swanlab table.

### 6. Validation max_tokens support (2026-06-03)
- **Added** `max_tokens: int = -1` field to `SamplingConfig` dataclass (`verl/workers/config/rollout.py`).
- **Updated** `rollout.yaml` to document `val_kwargs.max_tokens` (default: `-1` = use `rollout.response_length`).
- **Modified** `agent_loop.py` validation path to pass `max_tokens` to sampling params when `> 0`.
- **Modified** `hf_rollout.py` to override `response_length` during validation if `val_kwargs.max_tokens > 0`.
- **Updated** `recipe/respo/run.sh` to use `val_kwargs.max_tokens=${val_max_response_length}` (16K tokens).
- **Documentation** added at `docs/advance/validation_config.md`.
- **Purpose**: Allows validation to generate longer responses than training without padding waste during training rollouts.
